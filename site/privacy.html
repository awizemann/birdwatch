Privacy

Last updated August 18, 2026

Birdwatch is a local diagnostic tool. It reads the state of the iCloud sync daemons already running on your Mac and shows it to you — that's the entire product. Your files, file names, paths, sync data and account details never leave your Mac.

Your data stays on your Mac

Everything Birdwatch shows you — sync status, transfers, conflicts, logs, daemon stats — is read locally and stays local. Birdwatch has no server that receives it, and it is never sent to us or to anyone else.

Anonymous usage counts (you can turn this off)

So we know which parts of Birdwatch are actually used, the app sends a small number of usage events to our own analytics endpoint (api.swiftstats.co, run by us with the open-source swift-stats). What is sent: which screen was opened, which action was taken (for example “monitoring paused” or “daemon restarted”, and whether it succeeded), coarse counts such as “2–5 issues”, the Birdwatch version, the macOS version, device model and locale, and a random install identifier that is hashed before it leaves your Mac and cannot be tied to you, your Apple ID or your hardware.

What is never sent: file or folder names, paths, app names, device names, storage sizes, log lines, search text, your iCloud account, or anything typed. There is no advertising identifier, no fingerprinting and no cross-app tracking. Raw events are kept for 90 days; only daily totals are kept longer.

Turn it off any time in Diagnostics → Share anonymous usage. The switch persists, and while it is off nothing is collected or sent.

Software updates

Birdwatch checks for updates with Sparkle. That check fetches a small feed file from our site; it carries no personal information, and you can disable automatic checks the first time Sparkle asks.

No accounts

You don't sign in to Birdwatch, and it doesn't create or need an account. It uses whatever iCloud account is already signed in to your Mac, the same way Finder does.

Network activity

Apart from the two things above — usage counts and update checks — Birdwatch makes no network requests. It reads local system state — daemon status, log output, and sync metadata already present on disk and in memory — through system APIs such as brctl, NSMetadataQuery, and log stream. Any network activity you see reflected in the app (like estimated bandwidth) belongs to macOS's own iCloud daemons, not to Birdwatch.

What it reads, specifically

  • Sync status and progress from the CloudDocs daemon (bird)
  • Sync status and item counts from the CloudKit daemon (cloudd)
  • Domain status from File Provider extensions (fileproviderd)
  • System log output for these daemons, streamed locally
  • CPU and memory usage of these daemons, sampled locally

None of this leaves your Mac. Full Disk Access is required to read it, which is why Birdwatch asks for that permission on first launch.
