Privacy

Last updated October 6, 2026

Birdwatch is a local diagnostic tool. It reads the state of the iCloud sync daemons already running on your Mac and shows it to you — that's the entire product. Your files, file names, paths, sync data and account details never leave your Mac.

Your data stays on your Mac

Everything Birdwatch shows you — sync status, transfers, conflicts, logs, daemon stats — is read locally and stays local. Birdwatch has no server that receives it, and it is never sent to us or to anyone else.

Anonymous usage counts (you can turn this off)

So we know which parts of Birdwatch are actually used, the app sends a small number of usage events to our own analytics endpoint (api.swiftstats.co, run by us with the open-source swift-stats). This is the complete list of what is sent:

  • Every event carries its name, the time it happened, its position in the session, a random session ID, and a random install identifier that is hashed (SHA-256, salted) before it leaves your Mac and cannot be tied to you, your Apple ID or your hardware.
  • Sent automatically by swift-stats: the app opening (app_open), and the start and end of each session (session_start, session_end with the session's length in seconds).
  • Birdwatch's own events, each with only the details listed — the event's name first, then each detail's name and every value it can take:
    • a setup screen shown, once per screen per launch (onboarding_step_shown) — which one (step: welcome or grant_access);
    • setup finished (onboarding_completed) — whether Full Disk Access was granted (fda_granted) and notifications requested (notifications_requested);
    • a screen opened (view_shown) — which screen (view: overview, applications, drive, devices, issues, activity, diagnostics, bandwidth or storage) and how you got there (via: at launch, the sidebar, a keyboard shortcut, search, the menubar, or a link);
    • an app's detail page opened (app_detail_shown) — only its sync backend (backend: cloudDocs, cloudKit or fileProvider), never the app;
    • the menu-bar popover opened (menubar_opened) — how many issues, as a range (issue_bucket), and whether monitoring was paused (paused);
    • a search result chosen (search_used) — whether it was an app or a screen (result_kind: app or view) and how many results, as a range (result_bucket), never the search text;
    • refresh (refresh_forced), monitoring paused or resumed (monitoring_paused, monitoring_resumed), notifications marked read (notifications_marked_read) and a stuck item revealed in Finder (retry_item_revealed) — no details;
    • an app muted or unmuted (app_muted) — its sync backend (backend) and the new setting (muted);
    • an issue dismissed (issue_dismissed) — its severity (severity: warning, conflict or error);
    • an issue's button pressed (issue_action) — which button (action: review_versions, open_diagnostics or manage_storage) and the issue's severity (severity), never its text;
    • a conflict resolved (conflict_resolved) — whether you kept the current version or an other one (kept);
    • a stuck item moved to the Trash (retry_item_trashed) — whether it worked (outcome);
    • a maintenance action (maintenance_run) — which one (action: restart_daemon, or the diagnose command's diagnose_copy_command / diagnose_open_terminal buttons), which daemon (daemon: bird, cloudd or fileproviderd), whether it worked (outcome: ok; unconfirmed when the restart signal was sent but no restart was seen; or failed), and for a failure only its kind (error_kind: unknownDaemon, daemonNotRunning, pathNotAllowed or other);
    • your plan size set or cleared (plan_cap_set) — only which of the two (cleared), never the size;
    • System Settings › Apple Account opened from Birdwatch (account_settings_opened) — from which screen (from: storage or devices), and only if it actually opened;
    • once per launch, a health summary (snapshot_health) — how many apps use each sync backend (apps_clouddocs_bucket, apps_cloudkit_bucket, apps_fileprovider_bucket) and how many issues are open (issue_bucket), each as a range; how many of the three sync daemons weren't running (daemons_missing); and whether Full Disk Access and notifications are allowed (fda_granted, notifications_granted).
    Ranges are 0, 1, 2-5, 6-20 and 20+. The source of truth is UsageEvent.swift: an event or detail that isn't in that file isn't sent.
  • With each batch of events: the swift-stats version; Birdwatch's version, build number and bundle ID; the OS name and version; the Mac model and CPU architecture; your language and region settings; and whether the build is a debug or TestFlight build. Screen-size fields are always sent as placeholder values (0 × 0 at scale 1) — Birdwatch doesn't fill them in.

What is never sent: file or folder names, paths, app names, device names, storage sizes, log lines, search text, your iCloud account, or anything typed. There is no advertising identifier, no fingerprinting and no cross-app tracking. Raw events are kept for 90 days; only daily totals are kept longer.

Turn it off any time with Share anonymous usage, in Diagnostics or in Birdwatch's Settings (⌘,). The switch persists, and while it is off nothing is collected or sent.

Software updates

Birdwatch checks for updates with Sparkle. That check fetches a small feed file from our site; it carries no personal information, and you can disable automatic checks the first time Sparkle asks.

No accounts

You don't sign in to Birdwatch, and it doesn't create or need an account. It uses whatever iCloud account is already signed in to your Mac, the same way Finder does.

Network activity

Apart from the two things above — usage counts and update checks — Birdwatch makes no network requests. It reads local system state — daemon status, log output, and file metadata already present on your Mac — through system tools and APIs such as brctl, log, ps, nettop and file-system events. Any network activity you see reflected in the app (like estimated bandwidth) belongs to macOS's own iCloud daemons, not to Birdwatch.

What it reads, specifically

  • Sync engine state, remaining quota and retry queue from the CloudDocs daemon (bird), via brctl
  • Which iCloud Drive files are uploading or downloading, from file-system events and the files' own iCloud flags
  • CloudKit activity in the system log — which apps synced, and when
  • The File Provider apps listed in ~/Library/CloudStorage
  • System log output for these daemons, streamed locally
  • CPU, memory and network byte counts of these daemons, sampled locally (the network counts feed the estimated bandwidth view)
  • The sizes of iCloud files stored on this Mac, for the Storage view
  • To check whether Full Disk Access is granted, Birdwatch opens one of these files and closes it again without reading anything from it, stopping at the first that opens: Safari's CloudTabs.db, Bookmarks.plist and History.db in ~/Library/Safari, Messages' ~/Library/Messages/chat.db, and the system privacy database (/Library/Application Support/com.apple.TCC/TCC.db). Their contents are never read.

None of this leaves your Mac. Birdwatch asks for Full Disk Access on first launch so it can also watch your Desktop and Documents folders, which macOS protects; without it, Birdwatch doesn't watch or measure those two folders.
