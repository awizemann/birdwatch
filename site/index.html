Birdwatch

See what iCloud is actually doing.

macOS hides almost everything about how iCloud sync works. Birdwatch reads what the sync daemons themselves report — through brctl, the system log and the file system — and shows you per-app activity, files in transit, and what's going wrong, in a window or from the menu bar. Where macOS gives no number, Birdwatch says so — and it labels every estimate as one.

How it works

macOS doesn't expose the same detail for every app — so Birdwatch doesn't pretend it does

Sync on a Mac runs through three different system daemons, and each one lets an outside app see a different amount. Birdwatch reads whatever the daemon responsible for a given app makes available, and labels every screen with what that source can and can't tell you. That's the whole point of the app: no invented progress bars, no fabricated percentages, and every estimate marked as one.

CloudDocs (bird)

The most detail: which files are uploading or downloading (in flight or done — macOS gives no percentage), and the engine state and retry queue from brctl dump, for iCloud Drive and apps' iCloud Drive folders. Desktop & Documents transfers are watched only with Full Disk Access. Conflicting versions are found in iCloud Drive itself; Desktop & Documents and apps' own folders aren't scanned for conflicts.

CloudKit (cloudd)

Activity only, read from the system log for up to the last 30 minutes: an app appears once it has synced, with how recently and what kind of work. No per-item progress or counts exist for outside apps. Covers apps such as Photos and Safari.

File Provider (fileproviderd)

Listed only: Birdwatch finds these apps from their folders in ~/Library/CloudStorage and streams fileproviderd's log, but doesn't read their sync status.

Runs outside the App Sandbox and asks for Full Disk Access — here's why

The system data Birdwatch reads — brctl output, the system log, daemon CPU, memory and network counters from ps and nettop, and iCloud file flags — isn't reachable from inside the App Sandbox that Mac App Store apps run in. So Birdwatch runs unsandboxed, which is also why it's distributed directly rather than through the App Store.

Full Disk Access is required. Without it, reading iCloud Drive makes macOS ask for permission and hold every read until someone answers, so Birdwatch reads nothing in iCloud Drive until access is granted — setup asks for it, and if it's turned off later Birdwatch stops and says so. It's also what lets Birdwatch watch Desktop & Documents, which macOS protects.

Birdwatch reads sync state. The only things it changes are ones you ask for: restarting a sync daemon, resolving a file conflict, or moving a stuck item to the Trash. See the privacy page for what stays on your Mac.
