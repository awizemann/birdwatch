How it works

macOS doesn't expose the same detail for every app — so Birdwatch doesn't pretend it does

iCloud sync runs through three different system daemons, and Apple gives each one a different level of detail. Birdwatch reads directly from whichever daemon is responsible for a given app, and labels every screen with exactly what that source can and can't tell you. That's the whole point of the app: no invented progress bars, no fabricated percentages.

CloudDocs (bird)

Full fidelity: exact per-file download percent, upload complete/incomplete, and conflict versions. Covers iCloud Drive and Desktop & Documents.

CloudKit (cloudd)

Status and item counts only — there is no per-item progress API. Covers Photos, Notes, Messages, and Safari.

File Provider (fileproviderd)

Domain-level status only. Covers third-party apps like 1Password, Bear, and Craft.

Runs outside the App Sandbox and asks for Full Disk Access — here's why

The system data Birdwatch reads — brctl status, per-daemon logs, and NSMetadataQuery sync metadata — isn't reachable from inside the App Sandbox that Mac App Store apps run in. To read it, Birdwatch has to run unsandboxed and ask macOS for Full Disk Access, the same permission Time Machine and backup tools need. That's also why it's distributed directly rather than through the App Store.

Birdwatch only reads sync state — see the privacy page for what that means in practice.
